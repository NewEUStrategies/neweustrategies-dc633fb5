# Architecture rules

- Render minimized chats from the shared session-backed store, with a maximum of three avatar bubbles on mobile and compact pills on desktop, so restoration state stays consistent across responsive surfaces.
- Derive article table-of-contents activity from heading geometry in one animation-frame-throttled scroll listener, because narrow IntersectionObserver bands skip sections during fast scrolling.
- Build article-audio controls from shared stateful icon atoms, so the sidebar widget and global audio bar preserve identical geometry, animation, and theme contrast.
- Keep Kinetic Signal Notch labels as a no-wrap row (signal bars + title) with the action floating above it, left-aligned and close to the row; its gray tone comes from the `--nes-kinetic-action` token, and its font size and weight must be declared through the `[data-w-id][data-w-id][data-w-id] .nes-kinetic-shell .nes-kinetic-action` selector with `!important` (covering the inner spans too) *and* `data-typography-exempt` on the action and its children, because the per-widget Theme Design rules otherwise force the description size onto the action (`[data-description-root]`, 0-4-0) and stamp the description weight onto every descendant through the high-specificity `:is(p, span, a, ...)` branch; the action's arrow is sized in `em` minus 1 px (`height: calc(1em - 1px)`, `width: calc(1.1em - 1px)`, no vertical offset class) so it tracks the label's type size, never exceeds the letters, and sits exactly on the x-height-to-baseline band, and inherits its color, while its stroke is a deliberately thin hairline that never bolds up (`strokeWidth` 0.85 px, 0.7 px in the compact pill + `vector-effect="non-scaling-stroke"`, with the polyline inset from the edges of its em box) so the mark stays a subtle tick at any type size; container-based tightening for narrow widgets keeps bars, title, and action visible without overlap; the action never carries an underline (`.nes-kinetic-action` pins `text-decoration: none`, which also stops an underline set on the whole widget from propagating into it), and the variant draws no rule under the row until the editor's "Show rule" toggle turns it on (`showRule` defaults off for this variant alone, so other variants keep their line).

## 2. Which loading mechanisms exist in this build (verified in the artifact)

1. **Route-level CSS is SSR-linked by TanStack Start.** `.output/server/_tanstack-start-manifest_v-DcVEtS0X.mjs` carries
   `css:["/assets/RichTextView-DK8DYkTM.css"]` for `/$`, `/support`, `/checkout/success`, `/events/$slug/*`. CSS imported anywhere in a route chunk's
   static graph is rendered as `<link rel=stylesheet>` for that route only: no FOUC, no head parity issue (the same manifest drives client and server).
2. **Lazy-chunk CSS is loaded by the Vite preload helper** before the module runs (`index-DPN2YAij.js` deps list contains
   `assets/RichTextView-DK8DYkTM.css`). This is right for post-hydration UI (dock, chat, dialogs, popups, consent).
   It is NOT right for widgets rendered by SSR inside `React.lazy`, because their markup arrives before the CSS.
3. **React 19 Float resources** are already doctrine (`src/components/builder/organisms/widget-view/widgetStyleSheets.tsx:1-39`:
   `<style href precedence="nes-widgets">`). The same mechanism with `<link rel="stylesheet" href={url} precedence="nes-widgets">`
   (URL from `import url from "./x.css?url"`, the way `__root.tsx:21` imports `styles.css?url`) covers SSR-rendered lazy content:
   React emits the link in SSR and on the client, deduplicates it by href, and holds back the boundary reveal until it loads.
   Parity holds by construction.
4. `media="print"` link: never blocks render, and Chrome fetches it at lowest priority.

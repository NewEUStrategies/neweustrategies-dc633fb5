## 6. Conventions for implementation agents

- **Commits.** Polish subject in the form `Obszar[, runda N]: what changed, with numbers` (e.g. `Wydajnosc, runda 2: boot JS -16% raw / -15% gzip, ...`; `Wyszukiwarka w nagłówku: znacznik ... zamiast :has()`). Some subjects are ASCII-only, without Polish diacritics. The body lists each change (C1..Cn), the mechanism, the measured effect on the same artifact (before -> after), the gates that are green, and a doc pointer. End with the `Co-Authored-By` and `Claude-Session` lines. English `perf(scope): ...` subjects also exist (`f792321`, `c3fd92f`), but Polish is the house style. New prose uses a hyphen `-`, not an em dash (`HOMEPAGE_COLD_SSR §6`).
- **Docs.** `docs/performance/YYYY-MM-DD-<topic>.md` with: baseline numbers (source, date, LH version), mechanism, change table (files, mechanism), paired measurement on the same artifact and fixture, behaviour changes to know, and remaining work. Link it from `docs/performance/README.md`. **Avoid the line PR #466 edits.** Keep "acceptance targets, not claimed scores" wording: do not claim PSI scores without a production measurement.
- **Measurement.** Before/after only in pairs, in the same session, on the same `build:smoke` artifact, the same fixture, the document warmed to HIT, a brotli proxy, and 3-5 runs with medians (`przyczyny.md:600-609`: TBT varies ±120 ms between sessions). Use `measure-ab.sh` here. CI uses `first-visit.yml` (paired base/candidate) and `cms-widget-performance.yml`. Inventory proof: `BUNDLE_INVENTORY=1 bun run build:smoke && bun run report:chunk-inventory <chunk> --modules`.
- **Tests.** Every change ships focused vitest tests, including negative controls for gates (`src/lib/ci/__tests__`). Keep SSR/hydration parity tests: `renderToString` / `renderToPipeableStream`, held-chunk browser tests (`slow-first-fold.spec.ts`). Per-file coverage thresholds in `vitest.config.ts` must hold. Clock-dependent tests must freeze the clock (`check:clock-freeze`). New `src/**` files must be classified in `scripts/taxonomy/features.mjs` (`check:feature-taxonomy`).
- **Formatting and lint.** `prettier --check .` (CI `verify`, `format:check`), eslint with 0 errors (`react-refresh` warnings are tolerated), no `any` / `as unknown as` (`check:unknown-casts`).
- **Bundle budget moves.** Thresholds are frozen in `FROZEN_BUDGET_KB` (`check-bundle-size.ts:1752`). A change that **lowers** sizes should ratchet the budget down in the same commit, with a dated roman-numbered chronicle entry (next: XXII) that lists per-chunk moves and the formula (runner value + host-to-host delta, rounded up, +1 KB). Raising a budget is "OSTATECZNOŚĆ" (last resort) and needs the measured cause in the chronicle. Refresh `reports/bundle-baseline.json` from a green runner log (`--update-baseline`, entry V). Host vs runner differ: `spreadsheet.worker` is +18.5 KB on the runner.
- **Ownership.** `check:ownership` / `generate:codeowners` cover only admin routes (`src/routes/admin*`) and migrations, through `governance/ownership.json`. CODEOWNERS is generated (`* @NewEUStrategies` as default). Perf scripts and docs need no entry. A new `check:*` script needs a workflow step (`check:gate-coverage`) and must appear in `verify-static.ts` lists, or be listed there as artifact-only like `check:bundle`.

| PSI mobile 412@1,75, `calc(100vw - 64px)` = 348 |            640 |      **640** |
| 412@1,75, margines 16 / 24 px                   |      640 / 640 |    640 / 640 |
| PSI desktop 1350@1, `50vw` = 675                |            768 |          768 |
| 390@3 (iPhone), `calc` = 326                    |           1024 |          768 |
| 412@2,625, `calc` = 348                         |           1024 |          768 |

| 1440@2, `100vw` (full-bleed)                    |           2400 |         1920 |
| 1920@1, `50vw`                                  |           1024 |         1280 |

Wniosek: **640w na PSI mobile daje wyłącznie krok C** (LP-7), bo sama drabina zostawia 768w. 640w wygrywa dla każdego

## 2. Zmiany (lista plików i mechanizm)

### 2.1 `src/lib/cropSizes.ts`: drabina, adres renderowany, `srcset` domyślny

1. `RESPONSIVE_WIDTHS = [480, 640, 768, 1280, 1920] as const` (`:209`). Zaktualizować komentarz `:204-208`: górny wariant
   to 1920 (≤ 2500 zostaje prawdą), a 640 jest konieczne dla LP-7.
2. Nowa stała `LEGACY_AVATAR_RESPONSIVE_WIDTHS = [320, 480, 640, 768, 1024, 1280, 1536, 1920, 2400] as const`. Komentarz
   PL: wyłącznie dla awatara renderowanego przez `OptimizedImage` (decyzja właściciela 2026-10-08). Bez niej zmiana A
   zmieniłaby `srcset` awatara autora w `PostContextViews`.
3. Nowa czysta funkcja `renderedMediaUrl(url: string): string`. Zwraca `pathname + search + hash`, gdy
   `new URL(url).origin === PUBLIC_MEDIA_ORIGIN` i `pathname.startsWith("/media/")`. W każdym innym przypadku zwraca
   wejście bez zmian: adres względny, inny origin (także dodatkowe originy najemców), host techniczny Supabase,
   `data:`, błąd parsowania. Deterministyczna (stała z builda), więc daje parytet SSR i hydratacji.
4. `buildImageSrcSet`: gdy `widths === RESPONSIVE_WIDTHS` (domyślna drabina, porównanie referencji), każdy kandydat
   przechodzi przez `renderedMediaUrl`. Własne drabiny (miniatury, treść wpisu, mega menu, zespół, stara drabina
   awatara) zostają absolutne. Komentarz PL ma powiedzieć wprost, dlaczego reguła stoi na domyślnej drabinie:
   - wszyscy konsumenci domyślnej drabiny to `<img>`/preload/`Link` (tabela §1.2);
   - preload i `<img>` każdej trasy przesuwają się razem, bez edycji tras (także `index.tsx` P3.6b);
   - awatary i miniatury zostają bajt w bajt.
5. Bez zmian: `buildScaledImageUrl` (używa go też `GalleryBlock`), `buildTransformedImageUrl`, `buildAvatarSrc`,
   `buildAvatarSrcSet`, `qualityForWidth`, `isSupabaseStorageUrl`.

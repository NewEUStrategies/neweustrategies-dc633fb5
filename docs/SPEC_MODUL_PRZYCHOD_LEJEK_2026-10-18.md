### 4.1 Konwencje (każda migracja huba)

- Nazwa `^\d{14}_[a-z0-9_]+\.sql$`, wersja **> `20261018120400`**, w bloku wycinka (§4.2); **≤ 45 KiB** (`src/lib/ci/migrationSize.ts`; `bun run scripts/split-migration.ts <plik> --dry-run`); idempotentna (`IF NOT EXISTS`, `DROP … IF EXISTS`, `CREATE OR REPLACE`, `ON CONFLICT`); nagłówek PL `DEFEKT/ZMIANA/KOLEJNOSC/IDEMPOTENTNA/DOWOD` (wzór `20261012131000_sms_send_log.sql:1-58`) + `-- CIALO-Z: <wersja>` przy redefinicji istniejącej funkcji (wersja = najnowsza wcześniejsza definicja, tabela §4.8); `SET lock_timeout = '5s'` przy `ALTER TABLE` na gorących tabelach (`subscriptions`, `crm_leads`, `payment_orders`, `profiles`, `retention_feedback`).
- Tabele: `tenant_id uuid NOT NULL REFERENCES public.tenants(id) ON DELETE CASCADE`, RLS włączone, **`REVOKE ALL ON TABLE … FROM PUBLIC, anon, authenticated`** (produkcyjny `pg_default_acl`), `GRANT SELECT … TO authenticated` tylko tam, gdzie jest polityka odczytu, `GRANT ALL … TO service_role`, brak polityk INSERT/UPDATE/DELETE dla `authenticated` (zapis wyłącznie RPC/trigger `SECURITY DEFINER`).
- Polityki odczytu: finansowe `USING (tenant_id = (SELECT public.current_tenant_id()) AND public.has_role((SELECT auth.uid()), 'admin'::app_role))`; operacyjne `… AND public.is_admin_or_editor()`.
- Funkcje `SECURITY DEFINER` zawsze `SET search_path = public, pg_temp`, `REVOKE ALL ON FUNCTION … FROM PUBLIC, anon, authenticated` w tej samej migracji, potem jawne `GRANT EXECUTE` wg macierzy §4.4. RPC admina: tenant z `assert_admin_tenant()` albo `current_tenant_id()` + bramka roli; funkcje serwisowe: tenant z wiersza (nigdy parametr `p_tenant_id` w funkcji wywoływalnej przez rolę API); helpery wewnętrzne z prefiksem `_` mogą przyjmować `p_tenant`, bo **żadna rola API nie ma EXECUTE**.
- Emitery: `PERFORM public.emit_domain_event(<tenant>, '<agregat>', <id>::text, '<typ.literał.v1>', <payload>, <aktor>[, p_suppress_actor => true])` - **jedno wywołanie na typ**, literał typu jako 4. argument; w `EXCEPTION WHEN OTHERS THEN PERFORM public._log_emit_error(<tenant>, '<funkcja>', '<typ>'); RETURN NEW;`; `UPDATE` emituje tylko przy `IS DISTINCT FROM` na kolumnach znaczących; pieniądze: `environment = 'live' AND provider <> 'mock'`; klub `secret` i wpisy anonimowe nie emitują.
- Migracja czytająca `public.club_`/`public.admin_club_` poza migracją klubową S4 ma znacznik `-- pg-harness: exclude`.
- Brak nowych zadań `pg_cron`: harmonogram przez `jobs-tick` (§4.6).
